# P1-C — คู่มือทดสอบกับฮาร์ดแวร์จริง

> **ผลในเอกสารนี้ยังว่าง** — ต้องรันบนเครื่องที่มีบอร์ดต่ออยู่จริง
> เครื่องมือทั้งหมดพร้อมแล้วและถูกทดสอบกับจอจำลองแล้ว

---

## 0. ผลการ audit USB transport (จากซอร์สเฟิร์มแวร์ ไม่ใช่จากเอกสาร)

| หัวข้อ | ผล | ที่มา |
|---|---|---|
| ช่อง bridge | USB-Serial-JTAG ในตัว SoC | `pc_bridge.c:17,382-385` |
| console แยกเส้น | ✅ `# CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG is not set` | `sdkconfig:1995` |
| VID:PID | `303A:1001` (อยู่ใน ROM แก้ไม่ได้) | — |
| USB serial number | **ไม่รับประกัน** — descriptor อยู่ใน ROM | ไม่มี config ตั้งค่านี้ |
| tx/rx buffer | 1024 B | `pc_bridge.c:383-384` |
| **heartbeat** | **ทุก 5000 ms** | `pc_bridge.c:340` |
| โปรโตคอล | `PC_BRIDGE_PROTO_VER 1` | `pc_bridge.h:30` |

### สิ่งที่ต้องแก้เพราะ audit นี้

`offline_after_s` เดิม **10 s** ทน heartbeat หายได้แค่ 2 ครั้ง
สะดุดครั้งเดียวลิงก์จะเด้ง `OFFLINE↔ONLINE` และทุกครั้งที่เด้งจะลาก
mask จาก `FOLLOWING` → `STALE` → อาจถึง `CONFLICT` ทั้งที่ไม่มีอะไรผิด
**เปลี่ยนเป็น 16 s** = 3 heartbeat + margin (ปรัชญาเดียวกับ `missed_sample_limit = 3`)

### ความกำกวมของ VID:PID

`303A:1001` เป็นของ **ESP32 ทุกตัว** ที่ใช้ USB-Serial-JTAG ไม่ใช่ของ P4 ตัวเดียว
(โปรเจกต์ `espnow_c6` ในเครื่องนี้ก็เข้าข่าย)  ตัวเลือกพอร์ตจึง **ปฏิเสธที่จะเดา
เมื่อเจอมากกว่าหนึ่งตัว** แล้วบังคับให้ระบุ `--bridge-port` — เพราะการเปิดพอร์ตผิดตัว
ไม่ได้แค่ "ไม่ได้ข้อมูล" แต่ไป **ยึดพอร์ตของบอร์ดอื่นไว้ด้วย**

```bat
run_port_audit.bat
```

**ต้องปิด:** หน้าต่าง viewer  พอร์ตหนึ่งตัวเปิดได้ทีละโปรเซส

## 2. รัน

```bat
run_hw_test.bat --steps A,B,C,D                    :: ราว 15-20 นาที
run_hw_test.bat --steps E --soak 120               :: soak 2 ชั่วโมง
run_hw_test.bat --steps A,B,C,D --bridge-port COM7 --raw-capture
```

### รอบรวม (แนะนำ) — การวัดจริง + soak ในรอบเดียว

```bat
run_hw_test.bat --steps A,B,C,E --soak 120
```

ขั้น C จะรอสูงสุด **15 นาที** ให้คุณจุ่มหัววัด กด `Start run` รอ `STABLE`
แล้วกด `Save reading` **หนึ่งครั้ง** (ปรับเวลาได้ด้วย `--wait-measure`)
จากนั้นเข้า soak ต่อทันทีโดยที่ลิงก์ยังเปิดค้างอยู่ — ได้ทั้งหลักฐาน
ว่า `reading_saved` เดินทางถึง PC จริง และ soak ที่มีการวัดจริงเกิดขึ้น

⚠️ **ต้องเปิด logger เดิมค้างไว้ตลอด** ไม่งั้นขั้น A จะตกทันที และ soak
   จะไม่ได้พิสูจน์อะไรเลย เพราะข้ออ้างหลักคือ "bridge ไม่กวน logger"

เครื่องมือจะหยุดรอและบอกว่าให้ทำอะไรในขั้นที่ต้องใช้มือ
(เปลี่ยน mask บนจอ · กด Save reading · ถอด/เสียบ USB · กดรีเซ็ต)
แล้ววัดผลเองทั้งหมด

ผลออกที่ `data/diag/hwtest_<เวลา>.md` และ `.json`

## 3. เกณฑ์ผ่าน/ไม่ผ่าน — ตั้งไว้ก่อนเริ่ม

| ตัวชี้วัด | เกณฑ์ | เหตุผล |
|---|---|---|
| `csv_gap_max_s` | ≤ 3.0 | เกณฑ์เดิมจาก P1-A · วัดจาก **timestamp ในไฟล์** |
| `csv_rows_missing_pct` | ≤ 1.0 % | ตัวชี้วัดที่ไม่ขึ้นกับความละเอียด 1 s ของ timestamp |
| `hb_age_max_s` | ≤ 12 | heartbeat ทุก 5 s → เกิน 12 s = หาย 2 ครั้งติด |
| `link_drops` | 0 | เด้งเองโดยไม่ได้ถอดสาย = 16 s ยังไม่พอ |
| `malformed_total` | 0 | USB สะอาด เฟรมพังแม้เฟรมเดียวคือสัญญาณจริง |
| `stored_duplicates` | 0 | ซ้ำที่ถูก *ปฏิเสธ* มีได้ (จอ replay หลังต่อใหม่) |
| `queued_max` | ≤ 8 / 32 | เกินนี้แปลว่า PC ตามไม่ทัน |
| `heap_big_retain` | ≥ 0.90 | ชั่วโมงท้าย ≥ 90% ของชั่วโมงแรก |
| `process_exceptions` · `bridge_error` | 0 · None | |
| legacy | ต่อท้ายอย่างเดียว | ซอร์ส/เอกสาร/คอนฟิกต้องเท่าเดิมทุกไบต์ |

### ทำไมไม่มีเกณฑ์ p95 ของช่องว่าง CSV

คอลัมน์ `timestamp` ของ logger เดิมละเอียดแค่ **1 วินาที** ที่จังหวะ 2.5 s
ช่องว่างที่บันทึกได้จะสลับ 2 s / 3 s เสมอ → p95 = 3.0 โดยธรรมชาติ
การตั้งเกณฑ์ `p95 ≤ 2.8 s` จึงเป็นการอ้างความละเอียดที่ข้อมูลไม่มี
**เทสต์ที่ตกเพราะหน่วยวัด ไม่ใช่เพราะระบบ คือเทสต์ที่คนจะเลิกเชื่อ**
จึงใช้ "แถวหายกี่ %" แทน ซึ่งวัดสิ่งเดียวกันโดยไม่ติดปัญหาความละเอียด

## 4. สิ่งที่แต่ละขั้นตัดสิน

| ขั้น | ผ่านเมื่อ |
|---|---|
| **A** startup | เจอพอร์ตจอ · ได้ heartbeat ที่ใช้ได้ · CSV เดินหน้าต่อ · ได้ `display_mask` |
| **B** mask | `7→6→2→7` ตรงทุกขั้น · legacy ต่อท้ายอย่างเดียว |
| **C** saved reading | แถวใน UI 1 · `event_id` ไม่ซ้ำ · มี `stable_ec_us_cm` · legacy ไม่ถูกแก้ |
| **D** disconnect | ตกเป็น OFFLINE จริง · CSV เดินต่อระหว่างนั้น · ต่อกลับได้ · `boot_id` เปลี่ยนหลังรีเซ็ต · **ไม่มี reading_saved เพิ่มหลังต่อใหม่** |
| **E** soak | ทุกเกณฑ์ในตารางข้างบน |

## 5. ขอบเขต — สิ่งที่ยังพิสูจน์ไม่ได้

1. **ยังไม่ได้รัน** — เอกสารนี้คือขั้นตอน ไม่ใช่ผล
2. `--raw-capture` เป็นเครื่องมือวินิจฉัย **ไม่ใช่หลักฐานการวัด**
   ไฟล์ใน `data/raw/` มีทั้งเฟรมพัง เฟรมซ้ำ และเศษบรรทัด
   หลักฐานคือ `data/events/*.jsonl` ที่ผ่านการตรวจและกันซ้ำแล้ว
   (มีเพดาน 32 MB แล้วหยุดเอง เพื่อไม่ให้ดิสก์เต็มจนพา logger ล่ม)
3. `--mock` ของ `hw_test.py` มีไว้ทดสอบ **ตัวชุดทดสอบเอง** ไม่ใช่ทดแทนฮาร์ดแวร์
4. ยังไม่เปิดคำสั่งจาก P4 → PC ทุกคำสั่งได้ NACK เหมือนเดิม
5. ยังไม่มี Sensor 04
