## 1. ภาพรวมระบบ — ใครเป็นเจ้าของข้อมูลอะไร

จุดที่ทำให้หลงทางมานานคือ **eServer รวมข้อมูลจากหลายอุปกรณ์** ไม่ใช่จาก PLC ตัวเดียว

```
                        ┌──────────────────────────┐
   Wi-Fi router         │  eServer (SCADA ของ Delta) │
   192.168.1.1          │  โปรโตคอลเฉพาะของ Delta    │
        │               └────────────┬─────────────┘
        │                            │ อ่าน D-register ทั้งหมด
        ├── 192.168.1.20  Delta AS PLC ──┘
        │        │ Modbus TCP server (เปิดให้อ่านแค่บางส่วน) ← โปรแกรมเราต่อตรงนี้
        │        ├── MFC ×8  (4-20 mA / RS-485)
        │        ├── PT ×13, TI ×16
        │        └── (คาดว่า) poll ค่าแก๊สจาก Horiba มาเก็บใน D28089+
        │
        └── 192.168.1.100  HORIBA VA-5000  ← โปรแกรมเราต่อตรงนี้ด้วย (สำเร็จแล้ว)
                 Modbus TCP server ในตัว
```

โปรแกรมเปิด **2 การเชื่อมต่อพร้อมกัน** แต่ละอันมี unit id และ word order ของตัวเอง
(`workers/modbus_worker.py`) ถ้าอุปกรณ์ใดล่ม อีกอุปกรณ์ยังทำงานต่อ

## 2. ✅ HORIBA VA-5000 — จบแล้ว ใช้งานได้จริง

ยืนยันกับฮาร์ดแวร์จริง 2026-08-13 ทุกค่าอ้างจากคู่มือบทที่ 8 "External Input/Output"

| หัวข้อ | ค่า |
|---|---|
| IP / Port | `192.168.1.100` : `502` |
| Subnet / Gateway / MAC | 255.255.255.0 / 192.168.1.1 / 00-05-2B-0A-30-BF |
| **Slave address** | **255 (fixed)** — ไม่ใช่ 1 และเครื่องบังคับใช้จริง |
| Function code | 03 (Read Holding Registers) |
| **Word order ของ float** | **big** (high word ก่อน) — **ตรงข้ามกับ PLC ที่เป็น little** |

### Component → แก๊ส (ยืนยันโดยเทียบกับหน้าจอ MEASUREMENT ของเครื่อง)

| Component | Modbus | แก๊สจริง | Range | หมายเหตุ |
|---|---|---|---|---|
| 1 | `10506` | **CH₄** | 100 vol% | |
| 2 | `10508` | **CO₂** | 100 vol% | ← ตัวที่ Purity ใช้ |
| 3 | `10510` | **O₂** | 25 vol% | |
| 4 | `10512` | *ไม่ได้ติดตั้ง* | 0 | อ่านได้ 0.0, digits 0 |

> ⚠️ ธง "enable" ที่ `10858+` บอกว่า Component 4 เปิดใช้งาน **ซึ่งไม่จริง** —
> ให้ดู **Range = 0** กับ **Digits = 0** แทน

### 🔴 eServer ติดป้ายแก๊สผิดมาตลอด

eServer นิยาม tag แก๊สไว้ 4 ตัวผูกกับ float 4 ช่องติดกัน แต่เครื่องมีแค่ 3 ช่อง
ทุกอย่างจึงเลื่อนไปหนึ่งช่อง:

| eServer tag | ผูกกับ | **ค่าจริงคือ** |
|---|---|---|
| CO (D28089) | Component 1 | **CH₄** |
| CO2 (D28091) | Component 2 | CO₂ ✅ (บังเอิญตรง) |
| CH4 (D28093) | Component 3 | **O₂** |
| O2 (D28095) | Component 4 | *ไม่มีเครื่องวัด → 0 เสมอ* |

**เครื่องนี้ไม่มีการวัด CO เลย** ข้อมูลเก่าทุกไฟล์ที่มีคอลัมน์ `CO (vol%)` คือ CH₄
และคอลัมน์ `CH4 (vol%)` คือ O₂ — ต้องเปลี่ยนชื่อย้อนหลังก่อนนำไปใช้

### Register อื่นที่มีประโยชน์

| Register | ความหมาย |
|---|---|
| `10840` bit 9 / 16 / 18 / 19 | MEASURING / MAINTENANCE / auto-cal / auto-zero |
| `11520` | **0 = sample gas, 1 = calibration gas** |
| `10496`–`10501` | เวลาของค่าล่าสุด (ดูว่าค้างไหม) |
| `10874`–`10877` | หน่วยของแต่ละ component (0 = vol%) |
| `10882`–`10888` | ค่า range ของแต่ละ component (×100) |
| `10522`+ | ค่า O₂-corrected — **เราไม่ใช้** ใช้ค่าดิบที่ 10506+ |

> ⚠️ **ห้ามอ่าน address ที่ไม่อยู่ในตารางคู่มือ** — คู่มือระบุว่า
> *"may affect the performance of the analyzer"* ห้ามใช้ `scan_horiba.py`
> (ตัวกวาดสุ่ม) ยิงใส่เครื่องนี้ ให้ใช้ `read_horiba.py` เท่านั้น

### ข้อควรระวังตอนใช้งานจริง

- **sample flow ต้องไม่เป็น 0.0 L/min** (ดูมุมบนซ้ายหน้าจอเครื่อง) ถ้าเป็น 0
  ค่าที่อ่านได้คือแก๊สค้างในเซลล์ ไม่ใช่แก๊สจากคอลัมน์ PSA — กราฟจะนิ่งเป็นเส้นตรง
  ทั้งที่ระบบเดินอยู่ (สังเกตพบ 2026-08-13: CO₂ ไหลลง 14.51 → 14.24 → 14.16 ช้าๆ)
- **ถ้า `11520` = 1 แปลว่ากำลังไหล calibration gas** ค่าที่บันทึกจะไม่ใช่ค่ากระบวนการ
  แต่หน้าตาปกติทุกอย่าง — อันตรายกว่าเครื่องปิด เพราะเครื่องปิดเรารู้ทันที
- **register บอก "เครื่องปิด" ไม่มี** เพราะเครื่องปิดแล้วไม่ตอบอะไรเลย
  ให้ดูจาก TCP connect ล้มเหลวแทน

## 3. ⏳ Delta AS PLC — ยังไม่จบ

`192.168.1.20:502`, unit 1, float **word order = little**

### สิ่งที่รู้แน่

- ตาราง tag ของ eServer ตรงกับ `core/plc_map.py` **ทุกบรรทัด**
  (MFC-01=D100, MFC-06=D110, MF-07=D112, BPR-01=D114, PT1-1=D116, PT1-2=D118,
  PT2-1=D160 …) — **แผนที่เราไม่ได้ผิด**
- แต่ **Modbus address ≠ เลข D** ค่าที่อ่านได้ที่ address 110/112/114 ไม่ใช่ D110/D112/D114
- Modbus server เปิดให้อ่านแค่ 2 ก้อน (สแกน 2026-08-14):

  ```
  0 .. 1124     (1125 words, 26 non-zero)
  2000 .. 3124  (1125 words, 0 non-zero)
  ```

- ค่าที่ไม่เป็นศูนย์มีอยู่ไม่กี่ตัวและ**ขยับจริง** (เป็นค่าที่วัดได้ ไม่ใช่ค่าคงที่):

  | Addr | 2026-08-13 | 2026-08-14 |
  |---|---|---|
  | 102 | 0.001 | 0.002 |
  | 110 | −0.8 | −0.7 |
  | 112 | −0.8 | −0.8 |
  | 114 | −0.8 | −0.8 |
  | 116 | −0.9 | −0.8 |
  | 118 | −9.0 | −8.0 |

  **`118` = `116` × 10 พอดีทั้งสองครั้ง** → เป็นค่าเดียวกันคนละสเกล ไม่ใช่เซ็นเซอร์คนละตัว

### สิ่งที่ตัดออกไปแล้ว (อย่าลองซ้ำ)

| สมมติฐาน | ผลการทดสอบ |
|---|---|
| ขอให้ช่าง PLC ทำ MOV ก๊อปค่าแก๊สลง D ต่ำ | ❌ ไร้ประโยชน์ — เราอ่าน Horiba ตรงได้แล้ว |
| Delta offset +4096 (D0 = Modbus 4096) | ❌ สแกน 4000–12000 อ่านไม่ได้เลยแม้แต่ word เดียว |
| แผนที่ address ของเราเลื่อน | ❌ ตาราง eServer ยืนยันว่าตรงทุกตัว |
| ค่าซ่อนอยู่ในก้อนที่ตัวสแกนเก่าข้ามทิ้ง | ❌ ตัวสแกนใหม่ซอยย่อยแล้ว ได้ 2250 word เท่าเดิม |

### ผลกระทบที่ต้องระวัง

**MFC-07 และ BPR-01 ที่โปรแกรมแสดงตอนนี้เป็นค่าผิด** (−0.800 ทั้งคู่)
→ **อย่าเพิ่งกด File → Start recording เก็บข้อมูลจริง** จะได้ CSV ที่เลขผิดแต่ชื่อคอลัมน์ดูน่าเชื่อถือ
→ BPR-01 ผิด แปลว่า **ตัดรอบ cycle ไม่ได้ → Purity/Recovery แบบ cycle ไม่มีวันคำนวณออกมา**
(การ์ดแบบ 5 นาทีก็คำนวณจากค่าผิดเหมือนกัน)

ค่า CO₂ จาก Horiba เชื่อถือได้แล้ว

### ทางที่น่าจะจบเร็วที่สุด

น่าจะเป็นเรื่องที่ PLC **ไม่ได้ publish** D100–D206 ออกทาง Modbus (โปรแกรม PLC เลือกเปิดแค่บางช่วง)
ขอจากช่างเทคนิค PLC อย่างใดอย่างหนึ่ง:

1. **Modbus address จริงของ D100–D206** ที่ AS PLC เปิดให้อ่าน หรือ
2. ให้เพิ่มคำสั่งก๊อป D100–D206 ไปไว้ในช่วงที่เปิดอยู่แล้ว (`0–1124` หรือ `2000–3124`)
   แล้วบอกตำแหน่งมา

> ต่างจากคำขอครั้งก่อน (ที่เป็นทางตัน) ตรงที่คราวนี้เรารู้แน่ว่า**ข้อมูลอยู่ใน PLC จริง** —
> eServer อ่านได้อยู่ทุกวัน แค่ยังไม่ถูกเปิดออกทาง Modbus

## 4. หน่วยของ MFC-07 — ป้ายผิดแต่เลขถูก

- ตัวเครื่องคือ Brooks **SLA5850** full scale **20 NLPM** (MFC-01 คือ 1 SLPM)
- รหัสรุ่น `SLA5850S1BBC1C2A1` → ตำแหน่ง V = **S = RS485**, ตำแหน่ง X = **C = 4-20 mA**
  → **ไม่มีพอร์ต EtherNet/IP** คู่มือ EtherNet/IP ใช้กับเครื่องนี้ไม่ได้
- `analyzer.py` **ตั้งใจไม่แปลง SMLM → SLPM** (มีหมายเหตุกำกับในโค้ด) เพราะสูตรของแล็บ
  ใช้อัตราส่วนดิบแล้ว recovery ออกมา ~100% ตรงกับ Excel อ้างอิง
  → ตัวเลขอยู่ในหน่วย **L/min อยู่แล้ว** ป้าย "SMLM" คือป้ายผิดเฉยๆ
- **แก้เฉพาะป้ายเป็น NLPM ห้ามเติม ×1000** ไม่งั้น recovery เพี้ยน 1000 เท่า
- ⚠️ **ยังไม่สะสาง:** [steady_state.py:184](psa_analyzer/core/steady_state.py#L184)
  หาร ad_gas ด้วย 1000 แต่ [analyzer.py:143](psa_analyzer/core/analyzer.py#L143) ไม่หาร
  → ต่างกัน 1000 เท่า และ `steady_state` ถูกเรียกใช้จริงใน `main_window`

## 6. ผลเทียบตาราง tag ของ eServer กับ `plc_map.py`

เทียบทีละบรรทัดทั้ง 50 tag (2026-08-14): **ตรงกัน 49/50 ไม่มี MISMATCH**
ทั้ง address, ชนิดข้อมูล (FLOAT→float, UNSIGNED→uint16, SIGNED→int16) และ station
ของ TIC ทั้ง 7 ตัว รวมถึงจุดที่ผิดง่ายอย่าง `MF-08 = D316`, `PT-10 = D164`
และช่วงว่างของ TI (`D28128 → D28142 → D28242`)

ต่างเฉพาะกลุ่มแก๊ส 4 แถว ซึ่ง**ตั้งใจให้ต่าง** เพราะย้ายไปอ่านจาก Horiba โดยตรง

### ⚠️ ชื่อพ้องแต่คนละแก๊ส — ระวังตอนเทียบข้อมูลเก่า

| ชื่อ | ของเรา | ของ eServer |
|---|---|---|
| `CH4 (vol%)` | 10506 = Component 1 = **CH₄ จริง** | D28093 = Component 3 = **O₂ จริง** |
| `O2 (vol%)` | 10510 = Component 3 = **O₂ จริง** | D28095 = Component 4 = **ไม่มีเครื่องวัด** |

เราตั้งชื่อตามแก๊สจริง eServer ตั้งตามลำดับที่เข้าใจผิด

### 🔴 MFC-06 มีสามชื่อในสามที่

| แหล่ง | ชื่อ |
|---|---|
| ตาราง tag (config จริง) | **HG GAS** |
| Excel log (13 ส.ค.) | **WASTE** |
| `psa_live_test.csv` | **MIX** |

ในตาราง tag `MIX` คือ MFC-05 และ `WASTE GAS` คือ MF-08 → หัวคอลัมน์ในไฟล์ log
ใช้ชื่อแก๊สผิดตัว **เป็นอาการเดียวกับกลุ่มแก๊ส** (ชื่อเลื่อนช่อง)

สำคัญเพราะ MFC-06 เป็นตัวเดียวที่ไม่เป็นศูนย์ตอน idle (~0.07) — ยึดตามตาราง tag
คือ **HG GAS** (ระบบมี PT-HG และ TIC-HG อยู่จริง จึงสมเหตุสมผล)

### ชิ้นส่วนที่ยังขาด

ตาราง tag บอก STATION NO. แต่**ไม่บอกว่า station นั้นคืออุปกรณ์ตัวไหน IP อะไร**
ทุก tag เป็น station 1 / TCP/IP รวมถึงกลุ่มแก๊สที่พิสูจน์แล้วว่ามาจาก Horiba
→ **ขอหน้า "device / connection list" ของ eServer** (คนละหน้ากับตาราง tag)
ที่ระบุ station → IP / port / protocol จะตัดสินได้ทันทีว่า
PLC เป็นคน poll Horiba เอง หรือ eServer ต่อสองอุปกรณ์แยกกัน

## บันทึกรายวัน

### 2026-08-19 — 🔍 ข้อผิดพลาดของผมเอง: เราตามหาแต่ float เลยมองไม่เห็นข้อมูลครึ่งหนึ่ง

ผู้ใช้ท้วงว่า "จะมีแค่ตัวเดียวที่มีปัญหาได้ยังไง" — ถูกต้อง และเมื่อกลับไปอ่าน
`verify.txt` ที่ส่งมาให้ละเอียด พบความขัดแย้งที่ผมมองข้ามมาตลอด:

```
READABLE BLOCKS
     0 .. 1124   ( 1125 words, 25 non-zero )     <-- 25 word มีข้อมูล
NON-ZERO FLOAT VALUES
   110 =  -0.90   112 = -0.90   114 = 4.10
   116 =  4.10    118 = -651.00                  <-- อธิบายได้แค่ 10 word
```

**เหลืออีก ~15 word ที่มีข้อมูลจริง แต่เครื่องมือเรามองไม่เห็น** เพราะ
`scan_plc.py` ถอดรหัสเฉพาะ float32 ที่ address คู่เท่านั้น

หลักฐานยืนยันว่าข้อมูลแบบนั้นมีจริง มาจากหน้า Address ของ eServer เอง —
ช่อง TI ตั้งเป็น `Unsigned / Word / Read Count 1` คือเก็บเป็นจำนวนเต็ม 16-bit
หนึ่ง word ไม่ใช่ float สองword **อุณหภูมิ 29.5 °C จึงนอนอยู่ในหน่วยความจำ
เป็นเลข 295** — ตัวสแกนของเราอ่านข้ามไปทั้งหมด

#### สรุปสถานะการสื่อสาร (ตอบคำถาม "address ขึ้นมั้ย")

| ประเด็น | สถานะ |
|---|---|
| เชื่อมต่อ PLC | ✅ ปกติ `[OK] Connected. readable words: 2250 / 4001` ไม่มี timeout |
| ได้ค่ามาจริง | ✅ ได้ครบทุก word ที่ PLC ยอมให้อ่าน |
| **รู้ว่า address ไหนคือ tag อะไร** | ❌ **นี่คือปัญหาจริง** — ค่ามาโดยไม่มีป้ายชื่อ |
| มองเห็นค่าครบหรือไม่ | ❌ เห็นแค่ float — ที่เก็บเป็น integer หายไปหมด |

#### แก้เครื่องมือ → `scan_plc_v4.exe`

- เขียน **D3000 = 300** แล้ว **666** ผ่าน ISPSoft (หน้า Enter Present Value)

- ตั้ง **Address: 3001** พร้อมติ๊ก **PLC Addresses (Base 1)** → คือ protocol address 3000
- แปลว่า **link ใช้ได้ และ address = เลข D จริง**

#### ⚠️ กับดัก Base 1 / Base 0

Modbus Poll ติ๊ก "PLC Addresses (Base 1)" อยู่ → **เลขบนจอช่างมากกว่าเลขที่ส่งจริง 1**
ถ้าเอาเลข 3001 จากจอเขามาพิมพ์ในเครื่องมือเราตรง ๆ จะไปอ่าน D3001 แทน D3000 เงียบ ๆ

#### แก้ตามที่ผู้ใช้สั่ง 3 ข้อ

**1. IP → 192.168.1.5** ทุกที่ (6 ไฟล์, 19 จุด) ไม่เหลือ `.20` ในโค้ดแล้ว

**2. โหมดเลือก function code** — ช่อง **Function** ใน Address Explorer
ใช้ถ้อยคำเดียวกับ Modbus Poll เทียบกันได้บรรทัดต่อบรรทัด:

```
03 Read Holding Registers (4x)   <- D, Y, SR, T, C, HC, E
04 Read Input Registers (3x)     <- X เท่านั้น
01 Read Coils (0x)               <- บิต Y, M, SM, S
02 Read Discrete Inputs (1x)     <- บิต X, Y, M, ...
```

เลือก FC01/02 แล้วตารางเปลี่ยนเป็นตารางบิตอัตโนมัติ (ใช้ดูสถานะวาล์วได้)

**3. เลือก type ได้ ไม่ใช่แค่ float** — ตอนนี้ถอดรหัส **8 แบบพร้อมกัน**
เพิ่ม `int32 LE` / `int32 BE` เข้ามาให้ตรงกับคอลัมน์ Value (32bits) ของ ISPSoft:

```
Address    │ word │signed│ ÷10 │ ÷100│int32 LE│int32 BE │float LE│float BE
3000 D3000 │ 666  │ 666  │66.6 │ 6.66│  666   │4.365e+07│9.3e-43 │2.3e-37
```

**เพิ่มให้เอง: ปุ่ม "PLC addresses (Base 1)"** ติ๊กแล้วเลข address จะแสดงแบบเดียวกับ
Modbus Poll (D3000 โชว์เป็น 3001) แต่เลขที่ส่งจริงไม่ขยับ — กันพลาดข้อ Base 1 ข้างบน

#### บั๊กที่เจอระหว่างทาง

`_values_of()` เช็ค `hasattr(rr, "registers")` ก่อน — แต่ pymodbus ตอบ coil มาพร้อม
**ทั้ง** `bits` และ `registers` ที่ว่างเปล่า ทำให้การอ่านบิตทุกครั้งได้ผลลัพธ์ว่าง
"เชื่อมต่อได้แต่ไม่มีข้อมูล" → แก้ให้เลือก payload จาก function code ไม่ใช่จากว่า
attribute ไหนมีอยู่

- นาที 6.3 → MFC-01 ตกเป็น 0 (หยุด feed) พร้อมกับ MFC-07 กระโดดขึ้น +1.7
- นาที 8.2 → MFC-01 กลับมา 0.085
- CO₂ ลงถึงต่ำสุด 51.9 ที่นาที **8.5** แล้วเด้งขึ้น 53.1 ที่นาที 10.5

CO₂ ตอบสนองต่อการหยุด feed โดยมีเวลาหน่วงสมเหตุสมผล — สัญญาณที่ไม่เกี่ยวกัน
จะไม่บังเอิญสอดคล้องแบบนี้ ส่วนที่ตอน idle เราอ่าน −0.8 แต่ eServer แสดง 0
น่าจะเป็นเพราะ **eServer ตัดค่าติดลบเป็น 0 ตอนแสดงผล** (SCADA ทำกันปกติ)

**ทางเลือกสำรองสำหรับการตัดรอบ:** MFC-01 มีจังหวะเปิด-ปิดชัดเจนกว่า BPR มาก
ถ้าเรื่อง BPR ยืดเยื้อ อาจใช้ MFC-01 ตัดรอบแทนได้

### 2026-08-14

**ค้นพบ**
- สแกนช่วง 4000–12000 → อ่านไม่ได้เลย ตัดสมมติฐาน Delta offset +4096 ทิ้ง
- READABLE BLOCKS = 2 ก้อน (`0–1124`, `2000–3124`) ก้อนที่สองเป็นศูนย์ทั้งหมด
- พบว่า register `118` = `116` × 10 เสมอ และค่าในโซนนี้ขยับจริงตามเวลา
- สรุปเรื่องแก๊ส: เครื่องไม่มีช่อง CO เลย — tag ของ eServer เลื่อนไปหนึ่งช่อง

**แก้โปรแกรม**
- กราฟแยกเป็น 3 แผง: CO₂ / MFC-01 / MFC-07 (ลบแผง BPR-01 — ข้อมูลยังเก็บและยังใช้ตัดรอบ)
- เพิ่มการ์ด **Purity (5 min)** และ **Recovery (5 min)** ใช้สูตรเดียวกับ pipeline
  แต่รวมตามหน้าต่างเวลาแทน cycle → **ไม่ต้องพึ่ง BPR**
  (`core/analyzer.window_metrics`, `LiveBuffer.window_metrics`)
- คลิก sensor ในหน้า Machine & Sensor Status → เปิดกราฟ vs time ย้อนหลัง 30 นาที
- เปลี่ยนป้ายหน่วย MFC-07 เป็น NLPM (ไม่แตะสูตร)
- แถบสถานะค้างข้อความเตือนเมื่อเครื่องวิเคราะห์ไม่ตอบ ไม่ถูกข้อความปกติเขียนทับ
- แก้ป้ายสถานะ: ช่องแก๊สที่อ่านไม่ได้ขึ้น `✕ not exposed` เหมือนกันทุกช่อง
  (เดิม CO₂ ขึ้น "no signal" เพราะเป็นคอลัมน์บังคับ ทำให้ดูเหมือนคนละอาการ)
